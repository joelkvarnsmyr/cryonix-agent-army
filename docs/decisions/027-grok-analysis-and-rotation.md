# ADR-027: Grok Analysis Tool & Signal Hunter
**Date:** 2026-03-10 | **Status:** Active

**Origin:** Manual portfolio review session revealing need for on-demand AI market intelligence
**Relates to:** [ADR-005](005-grok-ai-validation-fail-closed.md) (Grok AI validation), [ADR-024](024-x-sentiment-refinement.md) (X sentiment)

## Context (Why)
The auto-trader's signal pipeline is reactive — it only acts on signals generated by the Python engine's technical analysis. There was no way to:
1. Get an on-demand AI assessment of the current portfolio
2. Discover opportunities outside the TA scanner's pattern set (narrative-driven, catalyst-based)
3. Cross-reference our positions against real-time X/Twitter and web sentiment
4. Auto-inject AI-discovered opportunities into the trading pipeline

During a 10-day trading drought (Feb 26 – Mar 8), we had no tool to understand WHY positions were stagnant or what the market was offering. Manual analysis via Grok led to closing ARB (+5.8% profit) and opening SOL — decisions the TA engine couldn't make.

## Decision (What)

### 1. `grok_analyze.py` — Interactive Analysis Tool
A CLI tool that pulls raw data from Postgres + Redis, builds full system context, and sends it to Grok (grok-4-1-fast-reasoning) with **xAI server-side tools**:
- **x_search**: Searches X/Twitter for real-time sentiment, buzz, and breaking news
- **web_search**: Searches the web for fundamentals, listings, unlock schedules, DeFi metrics

**6 analysis modes:**
| Mode | Purpose |
|------|---------|
| `--mode full` | Complete analysis (all sections) |
| `--mode portfolio` | Deep dive on current positions + performance |
| `--mode market` | Market overview + watchlist rating |
| `--mode social` | X/Twitter + Telegram signal cross-reference |
| `--mode opportunity` | Aggressive opportunity hunting |
| `--mode sentiment` | Multi-stage sentiment scoring per coin |
| `--ask "question"` | Custom question with full data context |
| `--raw` | Dump raw data (no Grok call, useful for debugging) |

### 2. `grok_signal_hunter.py` — Autonomous Signal Injection
A cron-driven script (every 30 min) that:
1. Calls Grok with structured JSON output prompt
2. Searches X + web for volume spikes, catalysts, dips, narratives
3. Validates signals (symbol format, confidence range, pattern type, SL/TP levels)
4. Injects qualifying signals into Redis `trades:pending`
5. The auto-trader then re-validates via Grok before executing (double AI gate)
6. Also publishes exit recommendations to Redis `hunter:exit:{SYMBOL}` for the rotation engine

### 3. Smart Rotation Engine (in `route.ts`)
When all position slots are full and a strong signal arrives:
1. `scorePosition(pos)` — scores each position (0-100pts) based on P&L, momentum, age, confidence
2. `scoreSignal(signal)` — scores the incoming signal (0-80pts) based on confidence, pattern quality
3. `trySmartRotation()` — if signal score beats weakest position by `min_score_advantage` (15pts), rotate
4. `executeRotationClose()` — market sells victim, logs trade, handles cooldown, frees slot

**Scoring breakdown:**
- Position: P&L (0-40), momentum/HWM distance (±15), age (±15), confidence (0-10), grid immunity (+1000)
- Signal: confidence (15-45), strong pattern bonus (+10), multi-pattern (+15), hunter source (+8)

## Consequences (How)

### Positive
- **Proactive trading**: System now discovers opportunities beyond TA patterns
- **Portfolio hygiene**: Weak positions get rotated out automatically instead of blocking slots
- **Information edge**: Real-time X/Twitter + web data via xAI tools
- **Double AI gate**: Hunter signals still pass through Grok validator before execution
- **Human-in-the-loop**: `grok_analyze.py` enables manual analysis sessions anytime

### Negative
- **API costs**: ~15K tokens per hunt cycle (every 30 min = ~720 calls/day)
- **Latency**: Grok calls take 15-40s — acceptable for 30min cycle
- **False positives**: AI may recommend trades based on hype without technical backing (mitigated by auto-trader's TA + Grok re-validation)

### Risks & Mitigations
| Risk | Mitigation |
|------|------------|
| Grok hallucinates symbols | Validate `/USDC` suffix, check Binance market exists |
| Over-rotation (churning) | `min_hold_minutes = 30`, `min_score_advantage = 15` |
| Hunter injects bad signals | Auto-trader re-validates each signal through full pipeline |
| API costs spiral | grok-4-1-fast-reasoning is cost-efficient; monitor via usage logs |

### Configuration
```toml
# cryonix.toml
[rotation]
enabled = true
min_score_advantage = 15    # Signal must beat position by this many points
min_hold_minutes = 30       # Minimum time before rotation eligible
```

### Cron Schedule

